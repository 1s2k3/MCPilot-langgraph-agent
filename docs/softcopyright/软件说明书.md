# MCP 智能体平台软件 V1.0 — 软件说明书

---

## 1. 软件概述

### 1.1 软件名称与版本

- **软件全称**：MCP 智能体平台软件 V1.0
- **英文名称**：MCP Agent Platform
- **软件简称**：MCP Agent Platform
- **开发完成日期**：2026-08-20
- **版本号**：V1.0
- **开发方式**：独立开发

### 1.2 开发目的

随着大语言模型（LLM）能力快速发展，模型上下文协议（Model Context Protocol，MCP）已成为连接 AI 应用与外部工具、数据源的开放标准。大量企业级工具（数据库、内部系统、第三方服务）正以 MCP 服务器形式开放能力。然而，将 MCP 工具接入到一个**生产可用的**智能体平台中，仍面临多项工程挑战：

1. **工具面动态化**：智能体的能力应随 MCP 服务器的接入而动态扩展，而非固化在代码中；
2. **可控性**：工具调用必须可授权、可审批、可追踪，防止智能体越权操作；
3. **持续性**：会话状态需持久化，支持崩溃恢复与中断续跑；
4. **记忆能力**：智能体需具备跨会话的长期记忆，形成用户偏好与事实积累；
5. **可评估性**：模型迭代与提示词调整必须可量化回归，避免"改一处坏全局"；
6. **可观测性**：智能体的每一步决策、工具调用、反思过程必须可回放、可审计。

本软件面向上述需求，构建了一个生产级单智能体平台，实现 **MCP 工具接入、任务规划（Planning）、记忆（Memory）、人工审批（Human-in-the-Loop）、评估（Evaluation）与可观测（Observability）** 的一体化能力。软件采用"开箱即跑"设计：未配置任何外部模型密钥时，以内置脚本化演示模式离线跑通完整智能体流程；配置密钥后即可切换真实大语言模型，实现零代码改动的平滑升级。

### 1.3 主要功能综述

本软件提供以下核心功能：

| 序号 | 功能 | 说明 |
|---|---|---|
| 1 | 智能体运行引擎 | 基于"计划—执行—反思—总结"（Plan-Execute-Reflect-Finalize）闭环的智能体运行框架，支持步骤规划、工具调用、结果反思与自我纠错 |
| 2 | MCP 工具接入 | 多 MCP 服务器管理（stdio / streamable_http 两种传输），工具命名空间隔离、连接测试、失联降级 |
| 3 | 任务规划与反思 | 结构化输出生成步骤计划；反思节点对执行结果评审，支持通过 / 修正重试 / 重新规划 / 终止 |
| 4 | 两层记忆 | 短期记忆（对话窗口 + 滚动摘要）+ 长期记忆（语义向量检索，跨会话持久化） |
| 5 | 工具权限与人工审批 | 细粒度工具权限策略（允许 / 询问 / 拒绝 + 通配符）；"询问"触发人工审批弹窗，支持会话级授权记忆 |
| 6 | 评估体系 | 数据集回放、确定性指标 + LLM 评审双通道评分、评估仪表盘、CI 回归门禁 |
| 7 | 可观测性 | SSE 实时事件流、事件持久化回放、时间线可视化、状态快照检查器、LangSmith 全链路追踪（可选） |
| 8 | 安全设计 | API 密钥加密存储（写后不可读）、敏感信息脱敏、网关鉴权、工具执行白名单 |
| 9 | 可视化前端 | 会话聊天、智能体配置、MCP 管理、密钥管理、评估中心、运行详情六个功能页面 |

## 5. 功能设计

### 5.1 智能体运行引擎

#### 5.1.1 运行闭环

本软件的核心是"计划—执行—反思—总结"闭环智能体运行时，图拓扑如下：

```
开始 → 上下文加载（读取线程历史 + 检索长期记忆）
     → 规划（结构化输出步骤计划）
     → 执行（流式执行当前步骤，可发起工具调用）
         ├─ 有工具调用 → 工具节点（权限校验 + 执行）→ 回到执行
         └─ 无工具调用 → 反思（评审步骤结果）
              ├─ 通过且还有步骤 → 下一步执行
              ├─ 失败且可修正 → 注入反馈重试
              ├─ 计划不可行 → 重新规划
              └─ 全部通过 → 总结（生成最终回答，不使用工具）
     → 结束（落库 + 异步提取长期记忆）
```

#### 5.1.2 节点职责

| 节点 | 职责 | 产出 |
|---|---|---|
| 上下文加载 | 读取检查点恢复会话历史；检索长期记忆 | 记忆上下文注入 |
| 规划 | 结构化输出步骤计划（含每步目标与工具建议） | 步骤计划 |
| 执行 | 流式调用模型执行当前步骤，自主决定工具调用 | 消息、工具调用 |
| 工具 | 权限校验（可触发人工审批）→ 执行工具 → 结果规范化回喂 | 工具结果消息 |
| 反思 | 结构化输出评审结论：通过 / 修正重试 / 重新规划 / 终止 | 状态流转 |
| 总结 | 基于全部步骤结果生成最终回答 | 最终回答 |

#### 5.1.3 运行护栏

为保证运行可控，内置五类预算护栏（每个智能体可单独配置）：最大规划步骤数（默认 8）、单步最大重试次数（默认 3）、最大工具调用数（默认 30）、最大模型调用数（默认 40）、运行超时（默认 600 秒）。任一护栏触发时系统优雅收尾：跳过剩余步骤进入总结节点，产出"部分完成"的回答并附带说明，而非中断崩溃。

#### 5.1.4 状态持久化与恢复

- 每次运行的状态（消息、计划、反思记录、授权缓存）通过 LangGraph 检查点机制实时持久化到 PostgreSQL；
- 服务崩溃或重启后，线程状态完整无损，可从任意节点恢复；
- 人工审批挂起状态同样持久化，恢复后可继续。

### 5.2 MCP 工具接入

#### 5.2.1 多服务器管理

通过管理界面（或 API）配置多个 MCP 服务器，支持两种传输方式：

- **stdio**：本地子进程方式（指定命令、参数、环境变量）；
- **streamable_http**：远程 HTTP 方式（指定 URL 与请求头，凭据加密存储）。

#### 5.2.2 工具命名空间

所有 MCP 工具以"服务器名_工具名"前缀注册，同名工具在不同服务器间互不冲突；前端可按服务器分组展示工具及其归属。

#### 5.2.3 可靠性保障

- **连接测试**：配置后可一键测试连通性并预览该服务器导出的全部工具清单；
- **失联降级**：服务器失联时其工具自动从智能体工具列表隐藏并发出警告事件，运行继续而不中断；
- **统一拦截器**：为所有 MCP 调用注入超时、重试与参数脱敏（密钥类字段打码）。

### 5.3 任务规划与反思纠错

#### 5.3.1 步骤规划

规划节点以结构化输出生成任务计划，包含步骤序列（每步含目标与建议工具）与一句策略说明。计划在界面实时展示，帮助用户理解智能体意图。简单任务自动退化为单步执行，不为简单问题付出额外规划开销。

#### 5.3.2 反思纠错

反思节点对照步骤目标评审执行证据（工具结果、文本产出），输出四类结论之一：

| 结论 | 行为 |
|---|---|
| 通过 | 进入下一步骤 |
| 修正重试 | 附带具体修正意见，执行节点带反馈重试（不超过最大次数） |
| 重新规划 | 新信息表明原计划不可行，回到规划节点 |
| 终止 | 任务无法完成，总结节点产出部分结果并如实说明 |

反思记录全程留存（反思日志），前端可查看智能体的"自我纠错轨迹"，评估指标直接衡量纠错有效性。

### 5.4 记忆管理

#### 5.4.1 短期记忆（对话窗口）

- 会话消息窗口默认 20 条；超过窗口时自动将最早消息压缩为一条摘要（保留关键事实与结论）；
- 窗口与摘要均存入检查点，线程恢复后短期记忆完整。

#### 5.4.2 长期记忆（语义检索）

- **写入链路**：运行结束后异步提取记忆（模型结构化输出：事实 / 偏好条目 + 重要度评分）→ 文本规范化去重 → 本地向量化（all-MiniLM-L6-v2，384 维）→ 写入记忆表；
- **读取链路**：新输入向量化 → 相似度 top-k 检索 → 拼装为记忆上下文注入规划节点；
- **主动读写**：智能体可通过 `remember_memory` / `forget_memory` 工具主动写入、删除记忆（受权限策略管控）；
- **溯源管理**：每条记忆记录来源运行，界面可跳转回当时的运行；支持编辑与删除以修正错误记忆。

### 5.5 工具权限与人工审批

#### 5.5.1 权限策略

每个智能体拥有一份工具权限策略（JSONB），按规则声明工具动作：

```json
{
  "rules": [
    {"tool": "calculator", "action": "allow"},
    {"tool": "mcp-demo.*", "action": "allow"},
    {"tool": "remember_memory", "action": "ask"},
    {"tool": "forget_memory", "action": "deny"}
  ],
  "default": "ask"
}
```

| 动作 | 语义 |
|---|---|
| 允许 | 工具直接可用 |
| 询问 | 执行前挂起，请求人工审批 |
| 拒绝 | 工具在绑定阶段即从模型工具列表隐藏（隐藏优于拦截，智能体不会"想到"被拒工具） |

规则支持精确匹配、服务器级通配符（如 `mcp-demo.*`）与全局通配符。

#### 5.5.2 人工审批流程

"询问"策略触发完整的人工审批闭环：智能体挂起 → 前端弹出审批对话框（展示工具名、参数、所属服务器）→ 用户选择"允许"或"拒绝"（可附反馈意见）→ 运行续跑。选择"本次会话允许"后，该授权写入会话状态（随检查点持久化），后续调用不再打扰。

拒绝的结果以普通工具结果消息回喂智能体（"用户拒绝了该操作，请更换方案"），智能体可自主改道——这是比直接报错更完整的人机协作。权限校验在服务端图内部强制执行，前端弹窗仅为交互层，绕过前端无法越权。

### 5.6 评估体系

#### 5.6.1 评估数据集

支持数据集的新建与管理。数据集条目包含：输入、期望工具调用序列、参考回答、评分标准（rubric）、类别与难度。

#### 5.6.2 评估指标

运行评估时逐条回放数据集，采集完整轨迹（工具序列、迭代次数、耗时、令牌用量），计算两类指标：

| 指标 | 类型 | 说明 |
|---|---|---|
| 工具序列精确匹配 / 前缀匹配 | 确定性 | 实际工具调用序列与期望序列比对 |
| 回答评分（1–5 分） | 模型评审 | 按评分标准 + 参考回答评审，附评分理由 |
| 成功率 / 错误率 | 确定性 | 运行状态汇总 |
| 平均耗时 / 平均令牌 / 平均迭代 | 确定性 | 轨迹汇总 |
| 反思修正率 | 确定性 | 反思后修正成功的步骤占比（衡量纠错机制有效性） |

#### 5.6.3 回归门禁与对比

评估运行可纳入持续集成作为回归门禁（脚本化模式默认开启，真实模型评估可选）。评估仪表盘支持两次运行（不同模型 / 不同预算配置）的指标对比，辅助版本迭代决策。

### 5.7 可观测性

#### 5.7.1 双轨观测设计

| 轨道 | 用途 | 可用性 |
|---|---|---|
| LangSmith 全链路追踪（可选） | 开发调试：完整追踪、每节点耗时与令牌、提示词回放 | 可关闭，平台功能不受影响 |
| 自建事件表 + SSE | 产品功能：实时时间线、状态检查器、记忆溯源 | 平台内建，始终可用 |

#### 5.7.2 事件总线

所有节点 / 工具 / 模型动作发布标准化事件（序号、时间戳、运行标识、类型、载荷），事件总线将事件扇出为两路：实时推送前端（SSE）与批量落库（PostgreSQL）。数据库落库失败不影响流式输出（记日志 + 队列重试）。

事件类型覆盖运行全生命周期：运行开始 / 计划创建 / 步骤开始 / 步骤完成 / 步骤失败 / 模型调用开始 / 模型增量输出 / 模型调用结束 / 工具调用开始 / 工具调用结束 / 反思 / 状态快照 / 中断 / 恢复 / 记忆写入 / 通知 / 错误 / 运行结束。

#### 5.7.3 前端可视化

- **时间线**：按序号渲染事件轨道，类型着色（模型 / 工具 / 计划 / 反思 / 中断），点击展开详情；
- **状态检查器**：每个节点结束后的状态快照序列，相邻节点差异高亮；
- **记忆溯源**：记忆卡片可跳转回来源运行。

### 5.8 安全设计

| 主题 | 方案 |
|---|---|
| API 密钥存储 | Fernet 对称加密（主密钥仅存在于部署环境变量）；密文落库；**接口永远只返回掩码，写后不可读**；运行时解密仅在发请求前的调用栈内 |
| MCP 服务器凭据 | 请求头凭据同样 Fernet 加密存储；子进程凭据经环境变量注入 |
| 敏感信息脱敏 | 工具参数与结果中的疑似密钥字段（key / token / secret / password）落库与回喂前统一打码；事件与状态快照输出前脱敏 |
| 工具权限 | 图内服务端强制；拒绝工具从模型工具列表隐藏 |
| 检查点安全 | 启用严格反序列化模式，防检查点注入 |
| 网关鉴权 | 可配置管理令牌，`/api/*` 强制校验（可选开启） |
| 提示注入缓解 | 工具结果在提示中标注为不可信外部数据；工具面刻意不含高危操作 |

### 5.9 前端界面

| 页面 | 功能 |
|---|---|
| 会话页 | 左侧线程列表；中间对话流（流式文本、工具卡片、计划面板、审批弹窗）；右侧检查器抽屉（时间线 / 状态 / 工具 / 记忆四个标签页） |
| 智能体配置页 | 名称、系统提示词、规划提示词、各节点模型配置、预算、工具权限矩阵 |

## 6. 操作说明

### 6.1 安装部署

1. 准备 Docker 环境（Docker Engine + Compose v2）；
2. 复制 `.env.example` 为 `.env`，按需填写配置（数据库连接、可选模型密钥、可选管理令牌）；
3. 执行 `docker compose up -d` 一键启动四个服务；
4. 浏览器访问前端页面（默认 80 端口）；后端 API 文档自动生成于 `/docs`；
5. 首次使用无需任何配置：未配置模型密钥时自动进入脚本化演示模式，可离线跑通完整智能体流程。

### 6.2 使用流程

1. **创建智能体**：在智能体配置页填写名称、系统提示词与工具权限策略；
2. **接入工具**：在 MCP 管理页配置服务器（本地进程或远程地址），测试连通并预览工具；内置演示服务器开箱可用；
3. **开始会话**：在会话页新建会话并输入任务，实时观察流式回答、计划面板、工具卡片与审批弹窗；
4. **人工审批**：当智能体请求调用"询问"策略的工具时，在弹窗中选择允许 / 拒绝（可附反馈 / 会话级允许）；
5. **检查运行**：在运行详情页回放时间线、查看状态快照、工具调用明细与记忆溯源；
6. **配置密钥**：在密钥管理页添加模型 API 密钥，启用真实模型（无密钥时自动使用演示模式）；
7. **运行评估**：在评估中心新建数据集、执行评估、查看指标并对比两次运行结果。

### 7.1 测试体系

本软件构建了三级测试体系：

| 层级 | 环境 | 覆盖内容 |
|---|---|---|
| 单元测试 | 无外部依赖 | 权限策略引擎、记忆提取与去重、工具结果截断与脱敏、事件契约、预算护栏、提示词构造（62 项） |

核心测试策略：**脚本化模拟模型（ScriptedLLM）** 按预设脚本返回确定性输出并记录全部调用请求，使智能体全链路行为可精确断言，测试可重复、可离线、可回归。

### 7.2 测试结果

- 单元测试 62 项全部通过；
- 集成测试 14 项全部通过（真实 PostgreSQL 环境）；
- 持续集成三个作业（代码规范 / 单元 / 集成）在每次提交时自动执行并保持绿色。

### 7.3 可靠性工程实践

在开发与测试过程中，针对并发与生命周期场景进行了多轮缺陷修复，典型问题与解决方案包括：

| 问题 | 根因 | 解决方案 |
|---|---|---|
| 事件回放缺失最终事件 | 事件总线关闭时与后台写任务并发消费队列，取消写任务导致最后事件丢失 | 改为哨兵唤醒 + 等待写任务按序排空，无竞态关闭 |
| SSE 流事件乱序 | 先回放数据库再订阅实时流，落库滞后时实时事件插入序列前部 | 改为先订阅再回放 + 序号去重，保证客户端收到的始终按序号升序 |
| 测试间检查点连接失效 | 检查点单例连接绑定于首个测试的事件循环，循环关闭后连接失效 | 测试统一会话级事件循环作用域，连接生命周期与测试会话对齐 |
| 审批拒绝后智能体循环请求 | 演示模型未感知拒绝反馈 | 演示模型识别拒绝结果后自主改道，与真实模型行为一致 |

## 8. 技术特点与创新

1. **生产级智能体基础设施一体化**：将规划、执行、反思、记忆、审批、评估、观测七大能力整合于一个平台，各能力通过统一事件契约与状态模型解耦协作，任一能力可独立替换升级。

2. **双轨可观测架构**：LangSmith（外部追踪，供开发调试）与自建事件表 + SSE（产品功能，实时回放）双轨并存，事件数据同时支撑时间线可视化、断线补拉、审计溯源三类产品能力。

3. **脚本化确定性测试驱动**：以 ScriptedLLM 模拟模型驱动全链路测试，实现智能体行为的精确断言与可重复回归，单元 / 集成 / 评估三级门禁自动化，这是"模型非确定性"场景下工程质量的保障创新。

4. **权限"隐藏优于拦截"策略**：被拒绝的工具在模型工具绑定阶段即隐藏，从源头杜绝智能体对受限工具的调用企图；审批、会话级授权、拒绝反馈改道形成完整的人机协作闭环。

5. **事件总线竞态安全的生命周期管理**：以哨兵驱动的事件持久化排空机制，保证运行结束事件在并发关闭场景下零丢失；SSE 订阅先于回放 + 序号去重，保证流式事件严格有序。

6. **零配置开箱即跑**：无任何外部密钥时以演示模式离线跑通完整智能体 / MCP / 评估流程，配置密钥即切换真实模型，开发、演示、生产三场景零代码切换。

7. **统一安全纵深**：密钥密文存储写后不可读、敏感信息四链路脱敏（回喂 / 检查点 / 事件 / 界面）、网关鉴权、严格反序列化，形成纵深防御体系。
